# 常见问题 —— bio-sketch-figure

## 1. 流程概览

| 本技能命令 | 作用 |
|---|---|
| `outline` | 输入研究主题（可带参考图）→ 生成每页要展示的科学内容大纲 |
| `styles` / `--style` | 列出 / 指定配图风格 |
| `render` | 按大纲逐页出图 |
| `all` | 上面两步一次跑完 |

产物结构与风格清单见 `SKILL.md`。

## 2. 出图规则

- **每页独立生成**：不出封面、不以其他页为参考；页间一致性靠完整大纲、原始主题、
  **风格锁**（`prompts/style_lock.txt` + 各风格 yaml 的 `palette`）与素材库共同保证。
- **参考图按页裁决**：顺序固定为 `用户图 → 风格图 → 命中素材`，依次填到
  `defaults.max_ref_images`（默认 5）。
  - 用户图不再跳过风格图（与旧版本不同）。
  - **风格基准分流**：**有用户图时以用户图为风格与构图的优先基准**，风格图降为「次要风格参考」；
    **无用户图时风格图为唯一风格基准**（提示词与角色标注都会据此措辞）。
  - **风格图必定获得一个名额**：所选风格带参考图时，用户图上限降为 `max_ref_images - 1`，
    用户图再多也不会把风格图挤掉（`max_ref_images=1` 时用户图让位、只留风格图）。
  - 素材**只在关键词命中当前页内容时才加入**，每页最多 `defaults.max_elements_per_page`
    （默认 2）个；没有命中就不加。
  - 日志行 `[出图] 第 N 页 参考图: …` 是唯一事实来源；素材角色标注为
    `【图N】元素素材「名称」— 请直接复用其造型、结构与配色`。
- 参考图会先压缩再使用：**风格图**用风格 yaml 的 `reference_max_kb`（`2.5D高级` / `2.5D 柔彩机制图` /
  `科研流程图` 已设为 400KB，以保留笔触与渐变细节），**其余参考图**用全局
  `image.reference_max_kb`（默认 200KB）；日志会打印 `[压缩] X KB -> Y KB`。
- `--concurrency` 默认 1（顺序）；需要加速可设 3。

## 3. 额度闸口（出图是计费操作）

- `render` / `all` **必须显式带 `--confirm`**，否则：
  - `render` 只打印计划（页数 = 预计出图张数、风格、参考图构成、比例）并以退出码 1 结束，
    **不发起任何出图请求**；
  - `all` 只跑大纲（文本额度），打印大纲与计划后退出。
- 看到计划后，先向用户报告「页数 / 风格 / 参考图 / 预计张数」，**得到明确同意再加 `--confirm`**。
- **断点续跑**：`render` / `all` 会**默认跳过已存在 `<页码>.png` 的页**，计划里的「预计出图」按
  待补页数计；失败后重跑同一条命令只补缺失页，不重复生成已成功页。
- **重绘（覆盖已有页）**：必须显式加 `--overwrite`，且**每次重绘前都必须先向用户说明并取得明确同意**
  （重绘同样计费）；闸口会打印「⚠ 重绘（覆盖已有）」行。**不得擅自加 `--overwrite`。**

### 文本额度（成本可控）

- 文本模型**只在 `outline` / `all` 的大纲阶段调用一次**；识图与大纲合并为同一次请求，
  不会因为带参考图而多扣一次。
- `render`、`check` **不会**调用文本模型；旧的 `check --ping` 连通性自检已移除。
- 文本模型**已关闭自动重试**：一次大纲最多发一个请求（最多一次计费）。失败就直接报错，
  需要时手动重跑 `outline`（那是一次新的、单次计费调用）。

## 4. 现象 → 处理

| 现象 | 处理 |
|---|---|
| `❌ 缺少 --style` | 正常闸口。运行 `styles` 把清单交给用户，拿到明确答复后再指定；不要加默认值 |
| `[!] 出图是计费操作…`（退出码 1） | 正常额度闸口。把计划交给用户，**得到明确同意后**再加 `--confirm` |
| `❌ 未配置规划/出图凭证` | 运行 `init`，或设置 `BIO_SKETCH_TEXT_KEY` / `BIO_SKETCH_IMAGE_KEY` |
| 访问凭证无效或没有权限 | 校对凭证（注意首尾空格），确认账户状态与额度 |
| 请求过于频繁 | 已自动退避重试；仍失败则等 1-2 分钟再试 |
| 服务端临时故障 | 已自动重试；持续失败请稍后再试 |
| 内容未通过审核 / 出图未返回结果 | 软化提示词里可能敏感的描述后重试 |
| 所选服务不支持识别参考图 | 移除参考图后重跑（不会静默降级） |
| 识别参考图失败 | 把提示原文转述给用户，让其选择移除参考图或稍后重试；**不要改用 agent 自带的看图能力** |
| 未能解析出内容大纲 | 服务未按要求格式输出；精简主题描述后重跑 `outline` |
| 大纲调用失败（网络/服务波动） | 文本模型不自动重试，直接手动重跑 `outline`；一次大纲最多一次计费 |
| 某页没有加入素材 | 正常：该页内容未命中任何素材关键词，或参考图名额已满（日志会显示「名额已满」）；不是错误 |
| 素材被选出但没进参考图 | 索引里的 `file` 不存在（`check` 会提示「文件缺失」），补齐素材或修正索引 |
| 单个页面出图失败 | 看 `failed.json` 的 `index` 与 `error`，修正后重跑 `render`（`--pages` 指向同一份）——已成功的页会自动跳过，只补失败页 |
| 提交流中断（网络/代理抖动） | 已自动处理：拿到任务号则转轮询恢复（不重复提交、不重复计费），未拿到则退避重试提交；仍失败再重跑 |
| 重跑时不想重画已成功的页 | 默认就会跳过；日志显示「跳过已生成 N 页」 |
| 想重绘/覆盖已生成的页 | 加 `--overwrite`，但**每次都必须先取得用户明确同意**（重绘计费）；计划里会打印「⚠ 重绘（覆盖已有）」行；不得擅自加 `--overwrite` |
| 代理导致连接不稳 / 连不上 | **本技能默认直连并忽略环境代理**（`HTTP_PROXY`/`HTTPS_PROXY` 不再自动生效）。只有显式设了 `text.proxy` / `image.proxy` 才走代理；显式代理连不上会自动降级为直连。**不要用 `proxychains4` 包裹运行**（LD_PRELOAD 层脚本绕不过） |
| 生成超时 | 稍后重跑；日志里的任务号可留作排查依据 |
| 风格参考图缺失 | 确认 `assets/styles/2.5d-advanced.png` 存在，或修正对应 yaml 的 `reference_image` |

## 5. 排错与复现

- `run.json` 记录了本次的 `style_id`、`style_lock_source`、`aspect_ratio`、
  以及**每页**的参考图裁决 `reference_plan`（`roles` / `reason` / `count` / `ref_kbs`），
  还有 `saved` / `skipped` / `failed`，可用于复现同样的条件与核对续跑结果。
- 风格参考图路径在 yaml 里**相对技能根目录**；换成绝对路径也可。
- 新增风格：在 `styles/` 下加一个 `<id>.yaml`（含 `name` / `id` / `instructions`，
  可选 `reference_image`、`aspect_ratio`、`palette` 与 `reference_max_kb`），`styles` 会自动列出。
- 新增素材：把图片放进 `sucai/`，在 `sucai/index.yaml` 补一条
  （`id` / `name` / `keywords` / `description` / `file` / `transparent`）；
  未入索引的图片不会被使用，`check` 会列出它们。
- 改脚本后跑：`python tests/test_bio_sketch_figure.py`（67 个用例，不需要凭证）。
- 只想确认环境而不消耗额度：`check` 不会调用文本模型，也不发起任何生成请求。

## 6. 边界（硬性）

- 未确认出图 → **不发起任何出图请求**（`render` 退出码 1；`all` 只跑大纲）。
- 服务不支持识别参考图，而用户又提供了参考图 → **报错停止**，不静默忽略参考图。
- 参考图识别被拒 → **报错停止**，不改用其他看图链路。
- 风格参考图缺失或不可读 → **报错停止**，不静默忽略。
- 所有识图、规划、出图**必须**由本技能脚本完成，不得用 agent 自带能力替代。
